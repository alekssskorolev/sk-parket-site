# Редактор первого экрана

Админка → Настройки → Фон первого экрана. Компьютер (от 700 px) и телефон
имеют отдельные фото, светлую/тёмную палитру текста и кнопок, масштаб,
позицию, яркость, силу/положение/ширину светлого градиента и затемнение справа.
«Сохранить черновик» не меняет сайт. «Опубликовать фон» публикует обе версии
вместе. «Вернуть предыдущий фон» возвращает предыдущую публикацию обеих версий,
включая исходные фоны после первой публикации. Предыдущая публикация одна;
повторный откат переключает между двумя последними вариантами.

Настройки лежат в поле `hero` существующего `sk_gallery_state`, отдельно от
галереи карточек и цен. У фона собственная ревизия; serializable-транзакции
и проверка ревизии защищают от потери правок из двух вкладок. Сохранение галереи
не меняет настройки фона. Изображения используют уже настроенное Object Storage
и `sk_gallery_media`. Черновик, текущая и предыдущая публикации включены в refs:
таймер очистки не удаляет используемые фоны. Неиспользуемые загрузки удаляются
существующим сборщиком после 24 часов. Загрузка сама по себе не публикует файл.

Сервер перекодирует JPG/PNG/WebP, удаляет EXIF, ограничивает число пикселей.
Компьютер: до 2400×2000 и 650 КБ; телефон: до 960×1600 и 250 КБ.
Слишком сложное изображение сверх лимита отклоняется с понятной ошибкой.
Клиент предварительно уменьшает исходник; файл до 40 МБ не передаётся целиком API.

Маршруты существующего gateway сохранены:
- GET/PUT `/api/admin/gallery?view=hero`: состояние и сохранение черновика;
- POST `/api/admin/gallery/publish?view=hero`: публикация; action=rollback — откат;
- POST `/api/admin/gallery/media` с heroDevice: загрузка для выбранного экрана;
- GET `/api/admin/gallery/media/{id}`: авторизованный предпросмотр;
- GET `/api/gallery?view=hero`: только опубликованные настройки, max-age=60;
- GET `/api/gallery/images/{id}`: только опубликованные изображения (текущие или предыдущие), max-age=300.

Все административные изменения требуют сессии, правильного Origin и CSRF.
UUID, принадлежность фото экрану, типы значений и диапазоны проверяются сервером.
Для предпросмотра используются именованные варианты существующих asset-маршрутов:
/gallery-admin.js?module=hero, /gallery-admin.js?module=hero-preview,
/engine.js?module=hero, /engine.js?module=hero-preview. Только HTML предпросмотра
разрешает встраивание с того же origin; остальные страницы сохраняют anti-frame CSP.
Изображения по умолчанию для iframe разрешены только с https://skparket.ru.

Предпросмотр собирается из настоящих header/hero и стилей сайта командой
`node scripts/build-cloud.mjs`; общий `hero-display.js` управляет и предпросмотром,
и публичным первым экраном. Ползунки работают локально, без сетевых запросов.
На сайт редактор не загружается. Старое встроенное фото вынесено из CSS:
вместо 326 КБ stylesheet — около 17 КБ плюс отдельный выбранный WebP.
Манифест кэшируется отдельно от прайса на минуту; каждый просмотр загружает
изображение только своего экрана. При долгом ответе API через 1,8 секунды
показывается исходное изображение; после получения настроек оно заменяется
опубликованным. При смене ширины через границу 700 px загружается другой вариант.

Первое включение редактора не публикует фон из присланной HTML-примерки:
на сайте остаются исходные фотографии, пока владелец не опубликует свой черновик.
Для показа без JavaScript сохранён responsive CSS fallback.

Проверки: `node --test cloud-functions/ydb-stage1/test/*.test.cjs`, `npm test`.
Браузерная интеграция с подменой API: `PLAYWRIGHT_MODULE=<путь к playwright> CHROMIUM_PATH=<chromium> node scripts/check-hero-editor.cjs`.
Она проходит загрузку двух фото, локальный предпросмотр, сохранение/публикацию/откат,
и проверяет, что мобильная и настольная страницы загружают только своё изображение.
