Получатель и отправитель: `korolev89@mail.ru`. Сайт остаётся на GitHub Pages,
обработчик — в существующей Yandex Cloud Function `skparket-api`.
SMTP: `smtp.mail.ru:465`, TLS с проверкой сертификата. Отдельная регистрация
в почтовом сервисе и перенос сайта не требуются.

## Первое подключение

1. Войдите в Mail.ru именно под `korolev89@mail.ru`. В настройках безопасности
   создайте пароль для внешнего приложения с доступом к почте (название: SK Паркет).
   Основной пароль от почты не использовать; пароль приложения не отправлять в чат.
2. В Yandex Cloud, в каталоге сайта, откройте Lockbox и создайте секрет
   `skparket-smtp`. В его версии добавьте пару: ключ `SMTP_PASSWORD`,
   значение — созданный пароль приложения. Не добавляйте его в GitHub или исходники.
3. Дайте сервисному аккаунту функции `skparket-backend`
   (`ajeo58qnnk9drt1hj0l7`) роль `lockbox.payloadViewer` только на этом секрете.
4. В workflow `.github/workflows/yandex-cloud.yml` привязка `SMTP_PASSWORD`
   указывает на секрет `e6qt2pn7us4hc9n74vm5`, версию `e6q45lckt83k3itlj5ku`
   и ключ `SMTP_PASSWORD`. Это публичные идентификаторы, пароль остаётся в Lockbox.
5. После попадания изменений в main workflow
   `Deploy skparket-api to Yandex Cloud` подключит пароль из Lockbox.
   Не добавляйте привязку только вручную в редакторе функции: следующий деплой
   управляет полным списком привязок через workflow.
6. Откройте защищённую админку → Заявки → блок почты →
   «Отправить проверочное письмо». Проверьте входящие и «Спам».
   Кнопка не создаёт заявку. Принятие SMTP-сервером ещё не подтверждает попадание во входящие.
7. Убедитесь, что существующий приватный минутный таймер вызывает
   `skparket-api/$latest`. Он теперь обрабатывает и почту.
   Проверьте вымышленной заявкой: сохранение в админке и письмо после запуска таймера.

Без пароля/полной конфигурации почтовая отправка выключена, админка показывает
незавершённое подключение. SMTP не проверялся реальным паролем при разработке.

## Доставка и хранение

Задание в `sk_email_outbox` создаётся в одной serializable-транзакции с заявкой
и ключом повтора, параллельно с действующим каналом MAX/Telegram. Повтор отправки
формы не создаёт нового задания. Запрос формы не ждёт SMTP.
Каждый запуск приватного таймера обрабатывает одно готовое письмо: lease 60 секунд,
повтор с задержкой до часа, TTL 7 дней. Письма содержат имя, телефон, комментарий,
полную сохранённую смету (если есть) и ссылку на защищённую админку. Контакты берутся
из заявки непосредственно перед отправкой; очередь не дублирует их.
Удаление заявки удаляет и почтовое задание. Старые заявки автоматически не рассылаются.

SMTP доставляет at-least-once: если сервер принял письмо, а подтверждение потерялось,
повтор возможен. Стабильный Message-ID помогает почтовым клиентам, но не гарантирует
отсутствие дублей. Пароль и ответы SMTP не выводятся в логи/ошибки интерфейса.
Для отзыва доступа удалите пароль приложения в Mail.ru. Для замены создайте новую
версию Lockbox, обновите ID версии в workflow и повторите деплой.

Доступ к полученным письмам и их удаление регулируются отдельно от удаления заявок
в админке; отправка письма создаёт дополнительную копию контактов в почтовом ящике.

Письмо содержит HTML-ссылку tel: для звонка и текстовую версию. Номер заявки находится внизу. При наличии расчёта прикладывается XLSX из того же генератора leadWorkbook, что используется в админке; цены не пересчитываются по текущему прайсу. Для заявок без расчёта и проверочных писем файл не создаётся.
