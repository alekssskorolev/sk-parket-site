# Пробная синхронизация цены материала

Админка → Настройки → Цены материалов. Единственная привязка: items/glue,
Berger Bond M1X 7 кг, артикул 156524, фиксированная карточка Parket-Sale.
Произвольные URL из админки не принимаются. Парсер подтверждает H1, артикул,
фасовку, наличие и цену за упаковку; не использует цены рекомендаций и JS-код.
Запрос выполняется обычным HTTPS, без браузера/LLM/платного API; TLS проверяется,
IPv4, общий таймаут 9 секунд, лимит ответа 2,2 МБ, редиректы только на тот же
товар у www.parket-sale.ru/parket-sale.ru. Цена должна быть 1000–100000 ₽.

Начальное состояние — ручной режим (выключено). «Проверить цену в магазине»
показывает результат, не меняя опубликованную цену. После включения переключателя
«Проверить и обновить сейчас» и расписание применяют корректную цену только к
этому материалу. Расход/размер упаковки, способ расчёта, состав и цена работ,
другие материалы и старые заявки не меняются. Для режима цены за м² вычисляется
новая ставка из цены упаковки и сохранённого расхода, без смены режима расчёта.
Изменение более чем на 30% или ошибка оставляют прежнюю цену и видимый статус.

Данные синхронизации — `priceSync` в JSON строки prices таблицы sk_admin_state.
Новых таблиц, сервисных аккаунтов, секретов и постоянно работающих серверов нет.
Правильная цена обновляет только glue в черновике и опубликованной конфигурации,
создаёт обычную новую версию прайса и запись истории. Несвязанные черновые правки
не публикуются. Если цена не изменилась, новая версия не создаётся.

Сохранение ручной правки glue через существующий changeState атомарно выключает
синхронизацию и аннулирует lease. Это касается также характеристик, упаковки,
расхода, способа расчёта, имени/активности материала. При выключении во время
HTTPS-запроса уже начатый запрос может завершиться, но его результат не применится.
Для включения черновик этого материала должен совпадать с опубликованным.
Изменение прайса в другой вкладке во время запроса блокирует применение результата.

Используется существующий приватный минутный таймер уведомлений. Только в окне
06:00–06:10 по Москве (03:00 UTC) производится проверка расписания; остальные
вызовы не делают дополнительных запросов для синхронизации. nextAt и lease
хранятся в той же транзакционной строке, поэтому две функции не загружают товар
повторно. До следующего дня повтор автоматической попытки не производится даже
при ошибке. При недоступности функции всё окно проверка переносится на следующий
день; всегда доступна ручная проверка. Локальный skipUntil сокращает контрольные
чтения БД, но корректность обеспечивают сохранённые nextAt/lease. Когда режим
выключен, автоматических HTTP-запросов к магазину нет. Ручные — не чаще раза в минуту.

Маршруты существующего gateway, с сессией/Origin/CSRF:
- GET /api/admin/config?view=price-sync — статус, опубликованная цена и результат;
- PUT тот же маршрут с {revision,enabled} — режим;
- POST /api/admin/publish?view=price-sync с {action:"check"} — проверка;
- /gallery-admin.js?module=price-sync — модуль интерфейса.

Затраты: дополнительное время существующей Cloud Function, немного операций и
хранения YDB. Отдельный триггер и новая функция не создаются; триггеры сами по
себе не тарифицируются, выполнение функций и YDB тарифицируются по потреблению.
Free tier Cloud Functions — 1 млн вызовов и 10 ГБ×час в месяц, общий для аккаунта.
Фактический нулевой счёт не гарантируется: есть другие задачи и ресурсы.
