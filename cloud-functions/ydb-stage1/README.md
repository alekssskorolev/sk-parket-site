# SK Паркет: закрытая проверка API в Yandex Cloud

Это этап 1, НЕ готовый публичный API. Сайт на GitHub Pages не менялся.
В архиве нет паролей, токенов, базы, заявок или node_modules.
Серверный пакет хранится отдельно от работающего сайта в cloud-functions/ydb-stage1/.
Ветка feature/ydb-api-stage1 не изменяет основную ветку и не переключает GitHub Pages.

## Что делает пакет

- GET /health: проверяет подключение к YDB запросом SELECT 1.
- GET /api/config: выдаёт config.seed.json из репозитория, version=1, leadsEnabled=false.
- POST /api/test-leads: записывает только тестовые контакты при TEST_WRITES_ENABLED=true.
- Пересчитывает приложенную смету на сервере общим движком public/engine.js.
- Сохраняет снимок сметы и priceVersion внутри orders.estimate.
- Реальный маршрут /api/leads всегда отвечает 503. API админки отсутствует.
- Фото не отбрасываются молча: запрос с ними отклоняется до записи.
- SQL параметризован; INSERT не перезаписывает существующие заявки при совпадении ID.
- Ошибки YDB/учётные данные не возвращаются посетителю.

## Важные ограничения

НЕ включать публичный доступ и НЕ переключать сайт на этот архив.
Защищённая админка, общие редактируемые цены, постоянный ограничитель запросов,
идемпотентность отправки, фотографии и Telegram ещё не перенесены на YDB.
Согласие в тестовой записи помечено test-only-not-a-real-consent и не считается реальным согласием.
Нет автоматического импорта localStorage: цены, изменённые в демо-админке браузера,
не попадут в YDB или seed автоматически. Перед переключением нужно отдельно
согласовать, какой прайс использовать. В комплекте seed из коммита
28585e77a861f86867a7e08d212fe1102ba14f7f репозитория alekssskorolev/sk-parket-site.
Не вводите реальные имена, контакты и персональную информацию в комментарий.
CORS не заменяет авторизацию. Этот пакет безопасно проверять только на закрытой функции.

## Загрузка

1. Сохраните ZIP на свой компьютер.
2. Cloud Functions → skparket-api → Редактор → Источник кода → ZIP-архив.
3. Загрузите skparket-api-stage1.zip. В корне архива лежат index.js и package.json.
4. Node.js 22; точка входа index.handler; память 256 МБ; таймаут 30 секунд.
5. Сервисный аккаунт skparket-backend; сеть не выбирать.
6. Сохраните существующие YDB_ENDPOINT и YDB_DATABASE без изменений.
7. Для тестовой записи добавьте переменную TEST_WRITES_ENABLED=true.
8. Публичный доступ НЕ включать. Создайте версию и дождитесь сборки.

Никаких новых таблиц для этапа 1 не требуется: используется уже созданная orders.
Не выполняйте CREATE TABLE повторно. Ранее записанная connection-test-001 останется.
Пакет может заменить её диагностический код в функции, но не удаляет эту запись из YDB.

## Проверка подключения

Во вкладке Тестирование вызовите функцию с данными {}.
Ожидается statusCode=200 и body с database=connected, leadsEnabled=false.
Если возвращается 503, проверьте старые переменные YDB и сервисный аккаунт.
Пакет не проверен на реальном облаке автоматически: локальные тесты используют подмену хранилища.

## Проверка сохранения

Содержимое файла test-event.json можно вставить в поле данных вкладки Тестирование.
Это HTTP-подобное событие Cloud Functions; body должен оставаться строкой.
Ожидается statusCode=201, ok=true и id вида test-<UUID>.
Повторный запуск этого теста СОЗДАЁТ новую тестовую запись (не обновляет прежнюю).

Чтобы увидеть записи, выполните в SQL-редакторе YDB:

```sql
SELECT id, created_at, name, phone, status, estimate
FROM orders
WHERE phone = '70000000000'
ORDER BY created_at DESC
LIMIT 10;
```

После проверки выключите TEST_WRITES_ENABLED или удалите эту переменную
и создайте версию. Не включайте публичный доступ.
Для удаления теста скопируйте конкретный id из результата и удалите только эту запись.

## Маршрутизация

Для будущего клиента маршруты передаются query-параметром route, например:
https://functions.yandexcloud.net/d4e98jo86kn9o7f75fia?route=/api/config
Закрытая функция требует IAM-аутентификации; обычное открытие URL в браузере не является тестом.
Не используйте integration=raw и не отключайте стандартную HTTP-обёртку Cloud Functions.

## Локальные проверки

Из папки function: npm ci --ignore-scripts
Из родительской папки: node --test test/*.test.cjs
Зависимости зафиксированы: ydb-sdk 5.11.1 и @yandex-cloud/nodejs-sdk 2.9.3.
Никакие запросы к реальной YDB автоматическими тестами не выполняются.
